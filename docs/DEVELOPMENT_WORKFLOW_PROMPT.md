## 2. 保留项目背景与用户真实问题

项目英文名：Photography Field Guide。
副标题：An Open Guide to Understanding Photography。
中文：摄影入门指南：从理解参数到独立创作。

读者不需要物理学基础。维护者是物理学博士生、摄影学习者，偏好控制变量、理解因果、静态摄影、城市建筑、街头、风景、旅行、人物、咖啡和静物，对 JPEG 直出与胶片模拟感兴趣。这些背景用于选择案例，不自动成为公开个人介绍。

保留以下问题作为持续选题依据，并按 QUESTION_BANK 更新状态：

- 全画幅、APS-C、“半画幅”与 M4/3 是什么，画幅系数从哪里来？
- 实际焦距、等效焦距、视角、取景范围与透视有什么区别？
- F 数值、入瞳、最大／当前／最小光圈是什么，为什么变光圈变焦仍可使用 F8？
- 光曝光、总光量、输出亮度、ISO、噪声和高光余量怎样关联？
- 快门、主体运动、相机抖动、防抖、自动对焦分别解决什么问题？
- 景深与背景虚化为什么需要比较条件？
- 高像素、镜头解析力、MTF、像差、衍射与实际细节有什么关系？
- P/A/S/M、Auto ISO、曝光补偿、测光和直方图怎样服务拍摄决策？
- RAW、JPEG、HEIF、EXIF、白平衡、胶片模拟、第三方配方、LUT 与后期有什么区别？
- 怎样观察光线、选择主体、组织背景、阅读作品、学习构图并形成表达？
- 照片为什么暗或糊，夜景、风景、人像有没有普适的“必用参数”？
- 如何整理、备份、导出和分享照片，怎样判断教程、样片与评测是否有用？

X-T5 与 XF16–50mm 是已知器材案例。通用教程和计算器默认用全画幅／APS-C 等概念，具体型号集中在器材页和明确标注的案例中。其他器材、原始问题与背景见 QUESTION_BANK 和 PROJECT_BRIEF，不编造用户作品、EXIF、体验或评价。

## 3. 内容呈现标准

每页先回答三个问题：我会学到什么？它解决什么实际困惑？接下来做什么？

- 每篇围绕一个核心问题。一个小任务通常只引入 2–3 个新概念；必要术语就地解释。
- 首屏提供简答、一个有解释力的图或例子、明确下一步。首屏所需的结论与操作保持可见。
- 段落一段一个意思，标题表达问题或结论，表格只用于真正需要对照的信息。
- 保留完整教学素材：问题、简答、直觉、原理、可视化、案例、误区、练习、延伸阅读、来源；根据阅读顺序合并组织，不机械堆成十个同等显眼的章节。
- 初学者主线与可选深读分层。推导、更多数值和技术限制按需展开；理解当前操作所必需的条件与错误提示保持可见。
- 图中有方向、尺度、单位、图例与文字解释；几何图、概念插画和实拍图片清楚区分。数值、图形和标签随同一状态更新；不能任意压缩角度或改变比例后仍称为精确几何。
- 比较图尽量只改变一个变量；多变量改变必须说明哪些因素同时变化。
- 示例设置明确标为示例。原创 SVG 可直接使用；真实照片需要明确授权、署名及可靠参数来源。
- 中英正文、图注、控件、错误、反馈与 SEO 含义一致，中文排版检查覆盖标点、粗体星号、单位与混排。
- 减少重复免责声明；首次交代比较条件后，就地给可操作结论与适用范围。

## 5. 把练习做成轻量任务游戏

最小闭环：选任务 → 知道目标 → 预测 → 做一次操作或观察 → 获得解释 → 自评／重试 → 下一步。

每个任务包括：

- 稳定任务 ID、版本、双语标题、学习目标、预计投入、所需物品、先修与相关教程。
- 最多三个主要步骤，逐步显示当前动作；高级说明可展开。
- 1–2 个明确条件下的概念问题、可选提示、答案解释和错误后的重试。
- 一个可在真实环境中完成的观察任务，以及简短反思清单。
- 可跳过、返回、重开和自由阅读的入口。学习内容不因答错或未完成任务而锁定。

区分两种反馈：

1. 客观概念题：只有在条件和答案能被验证时判断对错。解释因果，允许重试或查看答案；错误次数不扣学习进度。
2. 作品与审美：提供观察、自评和表达理由的清单，由读者标记。文案写“你已标记完成”，不能显示未经判断的“构图85分”“AI评审通过”或“已掌握摄影”。

可以使用轻量关卡、完成标记、进度和可选徽章；徽章只表示完成记录。首版不做排行榜、连续签到、倒计时压力、付费道具、强制解锁或与学习目标无关的积分系统。

技术上保持静态任务数据、原生控件、局部 TypeScript 和 SVG。首次只完成一个真正可用的任务，再复用其简单模式。不要先造大型游戏引擎或通用任务编排框架。

## 8. 科学与数据约束

- 物理焦距不随画幅变化；画幅系数通常按对角线定义。不同宽高比下，对角等效不保证水平与垂直视角同时相同；相机位置与透视关系要说清。
- N = f / D，D 为入瞳直径。区分光阑开口、最大／当前／最小光圈；不要编造变焦中间焦距的最大光圈曲线。
- 单位面积光曝光的理想相对模型为 H2/H1 = (t2/t1)(N1/N2)^2，说明场景、透过率等假设。总光量另需面积等条件。
- ISO 输出映射独立于入射光模型；固定光圈和快门下，提高 ISO 不表示捕获更多光子，不把名义输出比冒充真实 JPEG 像素亮度。
- F2.8→F4 约减少一档；log2(N) 滑块 1/6 才对应 1/3 档。快门的显示与解析不得改变真实时间，保留 0.8s、0.63s 和连续滑块调整回归。
- 景深、背景虚化、传感器噪声与像素解析力的结论都要声明比较条件；防抖不能冻结主体运动。
- 白平衡区分光源色温与相机补偿，给出固定条件下可操作的方向；胶片模拟、配方、RAW 显影和 LUT 分别说明。
- 器材用实际型号官方规格；通用 APS-C 示例尺寸不冒充 X-T5 的真实规格。
- 原创图示不伪造实拍或 EXIF。对主观表达保留多种合理结果，不制造唯一“好照片”答案。
- ID 唯一、双语配对、引用存在、先修无环、真实来源与审核日期都需验证。草稿退出生产路由、目录、sitemap 与搜索。

## 10. 每个小批次的工作流程

1. 查基线：实际 Git 状态、版本、代码、相关问题条目及既有测试。
2. 写短设计：读者问题、最少概念、主路径、状态与反馈、图示条件、数据／来源、具体文件和验收场景。
3. 完成一个可用的中英功能：内容、交互、错误与回退一起交付。
4. 自查实际呈现：阅读生成页面，完成整条使用路径，不能只检查源文件或页面标题。
5. 执行相关自动检查和浏览器检查，保存命令、环境、结果与限制。
6. 独立复核：有可用代理时，可分别检查科学内容、读者负担与工程；保持文件责任清楚。
7. 根据实测问题修改，并在同一场景复测；通过后更新 STATUS、问题库和路线图。
8. 给出可审阅结果：本批改了什么、为什么、测试了什么、哪些未跑、还剩什么。完成当前小批次后再扩张。

额度不足、进程中断或审批失败时，记录实际已写入文件、最后成功命令、失败原因、未完成步骤和临时进程；恢复后重新核对 Git 与代码，不从旧计划盲目接续，不把中断任务标为完成，也不绕过审批。

保持小规模、可复核改动；保留模板许可和现有工作。不得擅自 push、部署、公开仓库、绑定服务或更改内容／照片许可。创建本地检查点按当前会话已有授权执行；已有授权不重复询问，也不把其他 AI 的完成声明当作人类授权。
